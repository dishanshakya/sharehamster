## Android App
- Main source: `app/src/main/java/dev/sharehub/nepse/MainActivity.kt`.
- Home now follows a light market-dashboard design: NEPSE value/change summary, advances/declines/unchanged counts, a real intraday NEPSE area chart, and a compact Top Gainers table. Explore and Portfolio remain available.
- The app requests `https://nepse-api-gamma.vercel.app/api/market` over HTTPS with `HttpURLConnection`; JSON is parsed with `org.json`. It maps `liveMarket` quote fields (`symbol`, `securityName`, `lastTradedPrice`, `percentageChange`, `previousClose`) and NEPSE index ID 58 from `nepseIndex` (`currentValue`, `change`, `perChange`). It reads the graph values from `nepseIndexHistory` timestamp/value pairs.
- Old ShareSansar HTML scraping and the Jsoup dependency were removed.
- The app refreshes data on initial load and when manually refreshed. Vercel caches successful responses for 60 seconds, so repeated refreshes may show the cached response briefly.

## File Structure and API Contracts
- Android project source: `app/src/main/AndroidManifest.xml`; main UI, navigation, persistence, market parsing, and HTTP client are all in `app/src/main/java/dev/sharehub/nepse/MainActivity.kt`. Build configuration is in root `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`, and `app/build.gradle.kts`; `dev-android.sh` wraps build/install/relaunch.
- Backend source is the sibling `/home/lynx/dumbshit/sharehub-api`: `app/api/market/route.ts`, `app/api/stocks/[symbol]/route.ts`, `next.config.ts`, `package.json`, and `pnpm-lock.yaml`. `.next`, `node_modules`, Android `build`, and `.gradle` are generated/dependency output, not source structure.
- `/api/market` success JSON: `{ liveMarket: Quote[], securities: Security[], nepseIndex: Index[], nepseIndexHistory: [timestampSeconds, value][], fetchedAt: ISO8601 }`. `liveMarket` can be empty; in that case the route returns a security-list fallback in `securities` (observed deployed response has 571 entries). Quote fields used by Android: `symbol`, `securityName`, `lastTradedPrice`, `percentageChange`, `previousClose`, `totalTradeQuantity` or `lastTradedVolume`, `totalTradeValue`, `totalTrades` or `totalTradeCount`. Security fallback fields: `symbol`, `securityName`. Index objects include `id`, `index`, `currentValue`, `close`, `change`, `perChange`; NEPSE index is id 58. Error JSON is `{ error }` with HTTP 502.
- `/api/stocks/{symbol}` success JSON: `{ details: object|null, history: object[], fundamentals: { reported_eps: number|null, ttm_eps: number|null, last_date: string|null }|null, fetchedAt: ISO8601 }`; error JSON `{ error }` with HTTP 400 for invalid symbol or 502 on upstream failure. Fundamentals are scraped best-effort from NepseAlpha homepage embedded `earningSeasonTracker.data[]`; P/E is calculated client-side from quote price and positive TTM EPS. The current NepseAlpha payload does not include book value/share, so BVPS and P/B remain unavailable and are shown as `—`. Observed NABIL `details` keys: `securityDailyTradeDto` (with `openPrice`, `highPrice`, `lowPrice`, `totalTradeQuantity`, `totalTrades`, `lastTradedPrice`, `previousClose`, `businessDate`, `closePrice`, `fiftyTwoWeekHigh`, `fiftyTwoWeekLow`, `lastUpdatedDateTime`), `security` (including `symbol`, `listingDate`, `faceValue`, `securityName`, `activeStatus`, `companyId`), `stockListedShares`, `paidUpCapital`, `issuedCapital`, `marketCapitalization`, `publicShares`, `publicPercentage`, `promoterShares`, `promoterPercentage`, `updatedDate`, `securityId`. History records are objects with `closePrice` (the Android chart reads this).
- Fundamentals-source check: ShareSansar `/company/{SYMBOL}` serves a company page but explicitly gates “In-Depth Company Fundamentals and Data” behind SSPro; public NepseAlpha homepage embeds EPS figures (including reported and TTM EPS) but no book value/share field in the observed payload. NepseAlpha scraping is best-effort and can fail or change structure.
- Latest debug APK: `app/build/outputs/apk/debug/app-debug.apk`; debug-signed, rebuild after source changes.

## Vercel Backend
- Backend project is in sibling directory `/home/lynx/dumbshit/sharehub-api` (repository `https://github.com/dishanshakya/nepse-api`, branch `main`).
- Deployed API base: `https://nepse-api-gamma.vercel.app`; Android endpoint: `/api/market`.
- Built with Next.js and pnpm; endpoint uses `@rumess/nepse-api` methods `getLiveMarket()`, `getNepseIndex()`, and `getNepseIndexDailyGraph()`.
- Successful JSON response shape: `{ liveMarket, nepseIndex, nepseIndexHistory, fetchedAt }`. `nepseIndexHistory` contains timestamp/value pairs for the intraday graph. CDN caching is 60 seconds with stale-while-revalidate; cache is best-effort rather than durable storage.
- Backend keeps TLS verification enabled by default. `ENABLE_INSECURE_TLS=true` is an opt-in workaround only for upstream certificate failures; it weakens TLS security.
- The backend and package depend on unofficial NEPSE data; response shape and availability may change.
